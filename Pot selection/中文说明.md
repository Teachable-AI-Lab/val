# 锅选择逻辑 - 中文说明文档

## 📋 概述

这个文件夹包含了我们一起开发的**增强版 Overcooked AI 环境**，具有智能锅选择逻辑。系统现在可以区分多个锅（pot1 和 pot2），并根据前提条件做出智能决策。

## 🎯 主要功能

### 1. **锅的区分（pot1 vs pot2）**
- 系统现在将锅视为不同的实体，而不是通用的"pot"对象
- pot1 = 布局中的第一个锅
- pot2 = 布局中的第二个锅
- Agent 明确说明它要去哪个锅（例如，"go to pot1"而不是"go to pot"）

### 2. **玩家持有状态感知**
- HTN 方法现在检查玩家是否已经持有食材
- 防止玩家已经拿着物品时重复执行"get"动作
- **关键修复**：将状态事实格式从 `Fact(object='player_holding', status='onion')` 改为 `Fact(player_holding='onion')` 以匹配 HTN 前提条件

### 3. **智能 Boil 方法选择**
`boil` 方法现在有 9 种不同的实现，基于：
- 玩家是否持有食材
- 哪个锅是空的（pot1 或 pot2）
- 哪个锅有 1 个物品（准备完成配方）

### 4. **智能 Plate 方法选择**
`plate` 方法现在有 7 种不同的实现，基于：
- 玩家是否持有盘子
- 哪个锅有准备好的汤（pot1 或 pot2）
- 哪个锅正在烹饪（pot1 或 pot2）

### 5. **基于位置的路由**
- 新方法 `_get_route_to_position()` 用于路由到特定锅位置
- 增强的 `execute_action()` 处理 pot1/pot2/ready_pot1/ready_pot2 路由

## 🐛 修复的 Bug

### Bug 1: 无限递归循环
**问题：** Agent 一直尝试 `get(onion)`，即使已经拿着洋葱。

**原因：** 状态事实格式与 HTN 前提条件不匹配
- 状态生成：`{'object': 'player_holding', 'status': 'onion'}`
- HTN 期望：`Fact(player_holding='onion')`

**解决方案：** 更改状态生成以匹配 HTN 格式

### Bug 2: 无法区分锅
**问题：** Agent 无法区分不同的锅，总是去最近的锅。

**解决方案：**
- 添加 pot1 和 pot2 作为不同的状态事实
- 为特定锅创建基于位置的路由
- 使用锅特定的前提条件增强 HTN 方法

### Bug 3: 重复的 Get 动作
**问题：** Agent 会尝试获取已经持有的食材。

**解决方案：**
- 为"已经持有"的方法添加 `Fact(player_holding=V('object'))` 前提条件
- 为"需要获取"的方法添加 `NOT(Fact(player_holding=V('object')))` 前提条件

## 📊 对比：之前 vs 之后

### 行为变化：
1. **Agent 现在明确说明锅**："go to pot1" 而不是 "go to pot"
2. **没有重复的 get**：不会尝试获取已经持有的物品
3. **智能锅选择**：根据状态选择锅（装盘去准备好的锅，煮沸去空锅）
4. **没有无限循环**：修复的 player_holding 事实格式防止递归

### 性能改进：
1. **更少的失败动作**：前提条件防止无效的方法选择
2. **更高效的路径**：直接路由到特定的锅
3. **更好的资源使用**：可以有效地使用两个锅

## 🎓 关键学习点

### 1. HTN 事实格式至关重要
状态生成中的事实格式必须与 HTN 前提条件中期望的格式完全匹配：
```python
# HTN 期望：
Fact(player_holding='onion')

# 状态必须提供：
{'player_holding': 'onion'}  # 不是 {'object': 'player_holding', 'status': 'onion'}
```

### 2. 前提条件顺序很重要
具有更具体前提条件的方法应该首先列出：
```python
# 好：具体的在前
Method(preconditions=[Fact(player_holding='onion'), Fact(pot1='empty')])
Method(preconditions=[Fact(player_holding='onion')])
Method(preconditions=[])  # 回退最后

# 坏：回退在前会总是匹配
Method(preconditions=[])  # 会总是被选择！
Method(preconditions=[Fact(player_holding='onion')])
```

### 3. 使用 NOT() 条件进行否定
使用 `NOT(Fact(...))` 检查不存在：
```python
NOT(Fact(player_holding=V('object')))  # 玩家没有持有物品
```

## 📞 获取帮助

### 常见问题

**问：我可以在其他布局中使用这个吗？**
答：可以，但布局必须至少有 2 个锅才能进行 pot1/pot2 区分。单锅布局仍然可以工作，但不会从锅选择中受益。

**问：我可以添加更多锅（pot3，pot4）吗？**
答：可以！在 `get_state()` 中遵循相同的模式，并添加相应的 HTN 方法。

**问：这适用于多 agent 场景吗？**
答：是的，但你可能需要添加协调逻辑以防止锅冲突。

**问：我可以修改前提条件吗？**
答：可以！只需确保状态事实与前提条件格式完全匹配。
